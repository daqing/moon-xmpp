# RFC 6121 Roster and Presence E2E Testing with Adium

This guide manually verifies moon-xmpp's roster, presence subscription, and
presence broadcast support (RFC 6121 sections 2, 3, and 4) against a real local
XMPP server.

Adium logs in as `alice@localhost`; the moon-xmpp CLI logs in as
`bob@localhost`. The local server is Prosody running in Docker. This is the
manual Adium counterpart to `scripts/roster.sh`, which uses slixmpp instead.

## Prerequisites

- Docker Desktop is running.
- The MoonBit toolchain (`moon`) is installed.
- Adium is installed on macOS.
- All commands below are run from the repository root.

Prosody is the recommended local server on macOS. In particular, avoid the
ejabberd setup under amd64 emulation on Apple Silicon.

## 1. Start the server and create the accounts

```bash
scripts/prosody.sh start
scripts/prosody.sh register alice secret123
scripts/prosody.sh register bob secret123
```

Prosody listens on `127.0.0.1:5222` and requires STARTTLS. Registration is only
needed once until the container is recreated; an "already exists" error can be
ignored when repeating the test.

## 2. Configure Adium

Add an XMPP/Jabber account in Adium with these settings:

- JID: `alice@localhost`
- Password: `secret123`
- Connect server: `localhost`
- Port: `5222`
- Encryption: require STARTTLS; do not select direct SSL on port 5223

Adium will ask whether to trust the server's self-signed certificate. Accept it
only for this local test environment, then log in and set the account status to
Available.

## 3. Establish the presence subscriptions

Run the moon-xmpp side and keep the process running:

```bash
moon run cmd/main -- \
  --jid bob@localhost \
  --password secret123 \
  --host localhost \
  --port 5222 \
  --subscribe alice@localhost \
  --approve alice@localhost \
  --ca-file core/testdata/test_cert.pem
```

The options have distinct roles:

- `--subscribe` asks for permission to see alice's presence.
- `--approve` explicitly grants alice permission to see bob's presence. The
  library never approves an incoming request automatically.
- `--ca-file` makes the CLI trust the local test certificate.

In Adium:

1. Accept the authorization request from `bob@localhost`.
2. If Adium offers to subscribe to bob in return, accept that option.
3. Otherwise, add `bob@localhost` as a contact so that Adium sends its own
   subscription request to bob.

Depending on the order in which the two clients complete the handshake, the CLI
can print lines such as:

```text
* subscription Subscribe from alice@localhost
* roster: alice@localhost SubTo
* roster: alice@localhost SubBoth
* alice@localhost/<resource> is available
```

The resource name and the order of these lines are not significant. `SubTo` is
a one-way subscription; `SubBoth` is the expected final state after mutual
authorization. If no new request appears because the accounts are already
subscribed, reset the environment as described below before repeating the
handshake.

## 4. Fetch the roster in a fresh session

After the subscription exchange completes, stop the previous CLI with Ctrl+C
and run:

```bash
moon run cmd/main -- \
  --jid bob@localhost \
  --password secret123 \
  --roster \
  --ca-file core/testdata/test_cert.pem
```

A mutual subscription should produce:

```text
roster: 1 item(s)
* alice@localhost name="" subscription=SubBoth groups=[]
```

If the result is `SubTo`, only bob's subscription to alice has completed. Make
Adium subscribe to bob as well, approve alice's request with a CLI run using
`--approve alice@localhost`, and then repeat the roster fetch.

## 5. Verify presence broadcasts

Keep the `--roster` session running so that its receive loop continues to print
incoming stanzas. In Adium, set alice offline and then online again.

Going offline should produce:

```text
* alice@localhost/<resource> is unavailable
```

Coming back online should produce:

```text
* alice@localhost/<resource> is available
```

With mutual authorization, Adium should also show bob as available. Use an
offline/online transition for a clear check: an Away status is still an
available presence and must not be interpreted as `unavailable`.

## Resetting the test environment

To remove the test server together with its accounts, roster contents, and
subscription state:

```bash
scripts/prosody.sh stop
```

Start the server and register both accounts again before the next run. This
reset is useful when an existing subscription prevents Adium from displaying a
new authorization request.

## Automated equivalent

Run `scripts/roster.sh` for an unattended interoperability check. It uses
slixmpp rather than Adium, recreates the Prosody container, and checks the
incoming subscription request, the `SubBoth` roster state, and presence
broadcasts in both directions. Its transcripts are written to
`docs/acceptance/`.
